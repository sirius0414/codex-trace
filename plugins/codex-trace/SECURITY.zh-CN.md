# 安全政策

[English](SECURITY.md) | [简体中文](SECURITY.zh-CN.md)

## 支持版本

当前维护分支为 `0.2.x`，安全修复面向该分支的最新补丁版本。报告问题时请注明实际版本或提交 SHA；使用旧补丁版本时，请先检查最新版本是否仍有相同问题。其他版本不在当前安全维护范围内。

## 平台与数据边界

Codex Trace 在 macOS 或原生 Windows 上配合兼容的 Codex CLI 本地运行，不提供云端任务或网页端执行。平台要求及各版本的验证情况见 [INSTALL.md](INSTALL.md) 和 [WINDOWS.md](WINDOWS.md)；本政策不证明某项平台检查已经通过。

插件读取既有 Codex 任务记录，不修改这些来源；它会写入自身的派生摘要、阅读偏好、导出回执、临时快照及用户请求的 ZIP 导出。保存和删除详情见 [PRIVACY.md](PRIVACY.md)。涉及来源访问、路径限制、意外泄露或不安全写入的问题属于本政策的报告范围。

社区 Git 市场包通过 uv 在插件目录外准备 Python 和锁定依赖。首次准备、依赖变化或缓存缺失时可能需要网络。可选安装器与内置运行时产物采用不同的准备流程，请遵循对应安装说明。本地处理不代表依赖准备始终离线。

## 私密报告漏洞

可能涉及未授权读取、任务内容泄露、代码执行或其他安全边界的问题，请通过 [GitHub 私密漏洞报告入口](https://github.com/sirius0414/codex-trace/security/advisories/new) 提交，由维护者在私密报告中跟进。请勿将漏洞细节、复现载荷或未公开的修复方案直接发布到公开 Issue、PR 或讨论区。

此入口依赖公共仓库启用 GitHub 私密漏洞报告功能。若仓库为私有、入口不可用或没有 **Report a vulnerability** 按钮，请通过已有的维护者私密渠道联系，或等待私密渠道开放；不要改用公开 Issue 提交敏感细节。维护者应在公开发布前按 [GitHub 配置说明](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository) 启用该功能，并以普通访问者身份检查入口；本文件本身不会启用 GitHub 设置。

报告尽量包含：

- 受影响版本或提交 SHA、操作系统以及 Python/Codex 版本。
- 触发条件、最小复现步骤、预期行为和实际行为。
- 可能受到影响的数据或权限，以及已确认的影响范围。
- 使用合成数据构造的最小示例；如有修复建议，可一并提供。

不要上传真实任务轨迹、完整导出 ZIP、会话日志、访问令牌、API 密钥或其他人的个人信息。即使通过私密渠道，也请优先使用合成数据和经检查的最小错误摘要。若发现凭据已经泄露，请先由凭据所有者撤销或轮换，勿在报告中重复粘贴凭据值。

维护者会在私密报告中核实问题、协调修复和公开披露；响应及修复时间取决于实际影响和维护资源，不承诺固定时限。公开披露前请与维护者协调，避免暴露尚未修复用户的敏感信息。

## 普通问题反馈

不涉及安全或隐私的功能问题可以使用 [GitHub Issues](https://github.com/sirius0414/codex-trace/issues)。提交截图和错误摘要前，请检查其中的任务正文、本机路径、邮箱及凭据，确保没有真实私密内容。
